## Eventos e destinatários

| Evento | Origem | Destinatário |
|---|---|---|
| `TASK_ASSIGNED` | criação ou mudança de assignee da Task | novo assignee |
| `TASK_STATUS_CHANGED` | transição de status da Task | assignee atual |
| `REQUISITION_ASSIGNED` | criação, mudança de responsável ou adição efetiva de assignee | responsável atual |
| `REQUISITION_COMPLETED` | primeira definição de `deliveredAt` | responsável atual |
| `RELEASE_PUBLISHED` | publicação da Release | membros ativos com `releases.read` |

O ator nunca recebe a própria notificação. Membership e usuário precisam estar ativos no mesmo tenant. TimeEntries, pausas, Capacity, Timelines, vencimentos, menções e chat não geram eventos em M16.

## API

```text
GET   /companies/:companyId/notifications?limit=20
PATCH /companies/:companyId/notifications/:notificationId/read
GET   /companies/:companyId/notification-preferences
PATCH /companies/:companyId/notification-preferences
```

A listagem retorna somente dados do usuário autenticado, em `createdAt DESC, id DESC`, com `unreadCount` e `hasMore`. Marcar como lida é idempotente e o backend controla `readAt`. Preferências aceitam somente `{ eventType, inAppEnabled }`. Membership ativa basta; `notifications.manage` não é usada nem exposta.

## Persistência

A migration `0005_loose_lady_ursula.sql` tornou `notification_preferences.company_id` obrigatório, removeu `email_enabled`, adicionou `notifications.event_id` nullable e criou índices para ordenação, não lidas e deduplicação opcional por `(company_id, user_id, event_id)`.

Não há retenção, expiração, limpeza automática ou deduplicação para eventos sem `eventId` fornecido pela origem.

## Entrega e frontend

O único canal é a central in-app persistida. Não há WebSocket de aplicação, polling, refresh automático, EventSource, e-mail ou push. O frontend usa React Query com keys por `companyId`, `AbortSignal`, parser estrito, invalidação explícita e sem optimistic update.

A central usa `ResponsiveDialog`, foco inicial, trap de Tab/Shift+Tab, Escape, restauração de foco, indicador textual de não lidas e layout sem overflow nos viewports `320x844`, `360x800`, `390x844` e `1440x900`.
