## Implementado no worktree

### Backend

Endpoints novos:

```text
GET   /companies/:companyId/memberships
POST  /companies/:companyId/members
PATCH /companies/:companyId/memberships/:membershipId/permissions
GET   /companies/:companyId/capacity-settings
PATCH /companies/:companyId/capacity-settings
PATCH /companies/:companyId/releases/:releaseId
```

Contratos:

- listagem administrativa de memberships e usuários do tenant, protegida por `users.read`;
- criação atômica de User + Membership no tenant, protegida por `users.manage` e limitada aos cargos existentes, sem `MASTER`;
- substituição estrita de permissões explícitas da Membership, protegida por `permissions.manage`;
- leitura de `dailyHoursPerDeveloper` com `capacity.read` e alteração com `company.update`, reutilizando os use cases existentes;
- edição condicional de `versionLabel` e `channel` somente para Release `DRAFT`, com `releases.manage`;
- capabilities de Company expandidas para o catálogo real de permissões do backend;
- OpenAPI/Scalar e composition root atualizados para os novos contratos;
- nenhuma operação de ativação/inativação, promoção MASTER, reset de senha, status de Requisition ou storage/download de Release foi criada.

Use cases e infraestrutura adicionados:

- `CreateCompanyMember`;
- `ListCompanyMemberships`;
- `UpdateMembershipPermissions`;
- `MembershipUnitOfWork` e implementação Drizzle;
- `UpdateReleaseMetadata` com update de rascunho condicionado no repository;
- leitura administrativa tenant-aware reaproveitando e ampliando o repository de lookup de membros.
