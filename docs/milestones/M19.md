# M19 — Auditoria

## Objetivo
Registrar ações sensíveis com identificação de ator, tenant e entidade.

## Dependências
- M04–M06.

## Tarefas
1. Criar `AuditLog`.
2. Registrar login relevante.
3. Registrar alterações de permissões.
4. Registrar alterações de empresa.
5. Registrar criação, alteração e exclusão de requisição.
6. Registrar alterações de status.
7. Registrar publicação de release.
8. Registrar alterações de configurações.
9. Criar `GET /audit` com filtros.
10. Aplicar permissão `audit.read`.

## Critérios de aceitação
- Ações críticas geram auditoria.
- Ator e tenant são identificados.
- Nenhum dado sensível desnecessário é armazenado.
- Testes validam login, status e permissões.
- Endpoint é documentado via Scalar.

## Decisões existentes
- Auditoria deve registrar usuário, empresa, ação, entidade, identificador, timestamp e metadados mínimos.
- Auditoria não deve armazenar dados sensíveis desnecessários.

## Atomicidade

Tasks persistem a auditoria dentro da mesma `TaskUnitOfWork`, portanto rollback remove a alteração e o registro conjuntamente. As demais mutações usam o port de auditoria no application layer após a persistência bem-sucedida. A publicação de Release audita somente a atualização de metadados e `artifactLocation` no PostgreSQL; nenhum artefato é salvo ou acessado pelo Orbis e não foi introduzido outbox, retenção ou nova persistência.
