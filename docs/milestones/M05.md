# M05 — Autenticação JWT

## Objetivo
Implementar login, refresh token, rotação, revogação e logout.

## Dependências
- M04.

## Tarefas
1. Criar regras de credenciais.
2. Implementar `Login`.
3. Implementar `RefreshToken`.
4. Implementar `Logout`.
5. Criar access token de curta duração.
6. Criar refresh token revogável e armazenado com segurança.
7. Resolver o contexto autenticado.
8. Criar endpoints de autenticação.

## Critérios de aceitação
- Login gera access token e refresh token.
- Refresh rotaciona e revoga o token anterior.
- Logout revoga o refresh token.
- Rotas protegidas recusam token inválido ou ausente.
- Fluxos possuem testes.
- Senhas e tokens não são expostos em logs.

## Decisões existentes
- JWT é obrigatório.
- Access token contém claims mínimas.
- Refresh token não é usado para autorização da API.
- Refresh token é armazenado como hash.
- Endpoints: `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`.
