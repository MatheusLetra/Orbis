## Contratos consolidados

- O Kanban é uma projeção de Tasks agrupadas por `Task.status`.
- As colunas são `TODO`, `IN_PROGRESS`, `PAUSED` e `DONE`, nessa ordem.
- Drag and drop representa somente transições válidas da matriz de M09.
- Não há posição persistida, reorder intra-coluna, Board estrutural ou endpoint `/kanban`.
- `GET /companies/:companyId/tasks` aceita `scope=company|own` e pesquisa textual por título.
- A listagem retorna summaries mínimos de responsável e Requisition sem histórico, Attachments ou BYTEA.
- `GET /companies/:companyId/members` retorna membros ativos do tenant com `userId` e `name`.
- A listagem de Requisitions aceita pesquisa por título e, para termos numéricos, também por número.
- `GET /companies/:companyId/capabilities` retorna booleans efetivos para `tasks.create`, `tasks.update`, `kanban.manage`, `users.read` e `requisitions.read`, resolvidos por membership a cada request e sem expor tokens.
- O frontend consulta capabilities com query key tenant-aware, `AbortSignal`, stale time/retry globais e sem fallback permissivo.
- O Kanban exibe `Nova tarefa` somente após capabilities carregadas com `tasks.create=true`.
- A criação rápida usa modal HTML `dialog`, contém somente título e prioridade `MEDIUM`, não faz insert otimista e invalida apenas as listas do tenant ativo após sucesso.
- A edição usa o mesmo padrão acessível de `dialog`, permite somente título e prioridade, carrega os valores atuais, bloqueia submit duplicado, não faz optimistic update e invalida apenas listas e detalhe da Task no tenant após sucesso.
- O botão de edição só aparece quando `canEditTask` autoriza; Tasks `DONE` permanecem sem edição. O backend continua sendo a autoridade final.
- O detalhe da Task é aberto explicitamente a partir do `TaskCard`, usa modal HTML `dialog` acessível, carrega `TaskDetail` via `GET /companies/:companyId/tasks/:taskId` somente sob demanda, exibe campos completos e histórico de status, e reseta a seleção ao trocar de empresa.
- Attachments são carregados somente sob demanda no detalhe aberto, com listagem limitada a metadados.
- BYTEA não é carregado no Kanban nem no detalhe.
- O download de FILE ocorre somente após clique explícito, sem cache de Blob no React Query; LINK não possui download interno.
- O upload FILE ocorre sob demanda no detalhe, exige a capability existente `tasks.update`, usa multipart sem serialização JSON e não faz optimistic insert.
- O upload invalida somente a query `attachmentKeys.task(companyId, taskId)`, é abortável por lifecycle e não armazena BYTEA/Blob no React Query.
- Remoção de Attachments FILE/LINK em Task está concluída em M11.6B5C; auditoria manual em browser real permanece pendente.
- A criação de LINK ocorre sob demanda no detalhe, exige `tasks.update`, valida URL/título preliminarmente e fecha o detalhe somente após sucesso; Task `DONE` mantém a mesma política.
- A mutation LINK invalida somente `attachmentKeys.task(companyId, taskId)`, preserva o formulário em erro e aborta no lifecycle.
- A remoção de Attachment FILE e LINK em Task exige `tasks.update`, conforme o use case backend; a confirmação é explícita, não há remoção otimista e Task `DONE` segue permitida.
- Remoções de Attachments diferentes são independentes; cada operação invalida somente `attachmentKeys.task(companyId, taskId)`, com abort e proteção contra respostas stale.

### Autorização de criação e edição

- Criar exige `tasks.create`; sem assignee e para si é permitido; atribuir a terceiro exige também `kanban.manage`.
- Editar exige `tasks.update`. Com `kanban.manage`, o ator alcança qualquer Task não `DONE` do tenant.
- Sem `kanban.manage`, somente a Task atribuída ao ator pode ser editada, exceto que uma Task sem responsável pode ser assumida pelo próprio ator.
- Atribuir ou reatribuir para terceiro, editar Task de terceiro e remover assignee exigem `tasks.update + kanban.manage`.
- `kanban.manage` sozinho não substitui `tasks.create` ou `tasks.update`.
- A autorização de `UpdateTask` usa o assignee anterior e o novo assignee dentro da UoW, após `findByIdForUpdate`; ausência e cross-tenant permanecem 404.
