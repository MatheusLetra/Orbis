# M20 — Hardening, observabilidade e deploy

## Objetivo
Preparar o sistema para produção sem adicionar complexidade desnecessária.

## Dependências
- Todas as milestones anteriores.

## Tarefas
1. Consolidar logs estruturados, request ID e health check.
2. Medir duração das requisições.
3. Configurar rate limiting quando necessário.
4. Configurar CORS restritivo e headers de segurança.
5. Revisar validação de payload e uploads.
6. Revisar loading/error/empty.
7. Revisar acessibilidade e responsividade.
8. Validar temas, cor de destaque e densidade.
9. Criar Dockerfiles para API e app.
10. Configurar health checks de deploy.
11. Revisar `.env.example` e secrets.
12. Documentar eventual uso de RLS.

## Critérios de aceitação
- API é stateless e pronta para múltiplas instâncias.
- Observabilidade mínima funciona.
- Deploy sobe via containers ou processo documentado.
- Revisão de segurança é concluída.
- Health check completo funciona.
- Telas principais foram validadas em mobile e nos temas documentados.

## Decisões existentes
- Redis, Kubernetes e filas não devem ser adicionados sem necessidade concreta.
- RLS é evolução opcional.
- Storage S3-compatible para releases permanece dependente de decisão de produção.
- Segredos nunca entram no Git.
