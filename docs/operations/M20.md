# Operação M20

## Deploy

1. Configurar `DATABASE_URL`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `JWT_ISSUER`, `JWT_AUDIENCE` e `FRONTEND_ORIGIN`.
2. Em produção, usar HTTPS e `FRONTEND_ORIGIN` HTTPS.
3. Executar `cd API && npm run db:migrate` como etapa explícita antes da API.
4. Construir `API/Dockerfile` e `app/Dockerfile`.
5. Verificar `/health/live` para liveness e `/health/ready` para readiness.
6. Em encerramento, enviar SIGTERM e aguardar graceful shutdown.

## Backup

RPO: 24 horas. RTO: 4 horas. Executar backup PostgreSQL diário em formato custom, incluindo schema, dados e BYTEA de Attachments. Manter sete backups diários com acesso restrito. O backup não contém artefatos de Releases, pois o Orbis não os armazena.

```bash
pg_dump --format=custom --no-owner --no-privileges "$DATABASE_URL" > "orbis-$(date -u +%Y%m%dT%H%M%SZ).dump"
```

## Restore

Restaurar sempre em banco isolado:

```bash
createdb "$RESTORE_DATABASE"
pg_restore --clean --if-exists --no-owner --no-privileges --dbname "$RESTORE_DATABASE" "$BACKUP_FILE"
```

Após restore, validar migrations, contagens, checksum dos Attachments, `artifactLocation` das Releases e smoke de login, listagem e download de Attachments. Nenhum restore deve tentar resolver uma localização de Release.
