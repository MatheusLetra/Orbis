# M07 — Catálogo de software

> O modelo histórico de storage desta milestone foi substituído por M20. Releases atualmente persistem somente `artifactLocation`; o Orbis não armazena artefatos.

## Objetivo
Implementar `System → SystemVersion → Release` com armazenamento de artefatos abstraído.

## Dependências
- M04.
- M05.
- M06.

## Tarefas
1. Criar CRUD de sistemas.
2. Criar CRUD de versões.
3. Criar releases vinculadas a versões.
4. Persistir metadados das releases.
5. Criar porta `ArtifactStorage`.
6. Implementar `LocalArtifactStorage`.
7. Preparar storage S3-compatible para produção.
8. Validar permissões e isolamento tenant.

## Critérios de aceitação
- CRUD de sistemas e versões funciona com isolamento tenant.
- Release é vinculada a uma versão.
- Publicação grava metadados e localização manual.
- Testes de permissionamento e isolamento passam.
- Artefatos não são armazenados pelo Orbis.

## Decisões existentes
- O contrato histórico de `ArtifactStorage`/`LocalArtifactStorage` foi removido em M20.
- Releases não usam filesystem, PostgreSQL BYTEA ou provider externo.
- Anexos de requisições e tarefas usam PostgreSQL, não essa porta.

## Status
Concluída.
